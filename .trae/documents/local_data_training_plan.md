# 基于本地数据训练模型的实现方案

## 一、项目现状分析

### 现有代码结构
- **数据处理**：`app/services/data_service.py` - 负责数据处理和图构建
- **模型训练**：`app/services/model_service.py` - 负责模型训练和评估
- **模型实现**：`app/models/` - 包含LightGCN和LightGCN+KG模型
- **知识图谱**：`app/services/knowledge_graph_service.py` - 负责知识图谱特征提取

### 现有依赖
- Neo4j数据库：用于获取景点数据和构建知识图谱
- PyTorch和PyTorch Geometric：用于模型训练

## 二、本地数据训练方案

### 1. 本地数据格式设计

#### 1.1 景点数据格式 (`data/spots.json`)
```json
{
  "spots": [
    {
      "id": "spot1",
      "name": "故宫博物院",
      "city": "北京",
      "type": "文化古迹",
      "rating": 4.8
    },
    {
      "id": "spot2",
      "name": "长城",
      "city": "北京",
      "type": "文化古迹",
      "rating": 4.9
    }
  ]
}
```

#### 1.2 用户足迹数据格式 (`data/footprints.json`)
```json
{
  "user_footprints": {
    "user1": ["spot1", "spot2", "spot3"],
    "user2": ["spot2", "spot4", "spot5"],
    "user3": ["spot1", "spot3", "spot5"]
  }
}
```

#### 1.3 数据集分割格式 (`data/split.json`)
```json
{
  "train_users": ["user1", "user2"],
  "test_users": ["user3"]
}
```

### 2. 本地数据加载器实现

#### 2.1 创建本地数据服务 (`app/services/local_data_service.py`)
- 从本地JSON文件加载景点数据
- 从本地JSON文件加载用户足迹数据
- 实现与现有`data_service.py`相同的接口
- 提供数据分割功能

#### 2.2 修改数据处理器 (`app/services/data_service.py`)
- 添加本地数据加载模式
- 支持从本地文件或数据库加载数据

### 3. 模型实现

#### 3.1 UserCF模型 (`app/models/usercf.py`)
- 实现基于用户的协同过滤算法
- 支持余弦相似度和皮尔逊相关系数
- 实现Top-K推荐功能

#### 3.2 GCN模型 (`app/models/gcn.py`)
- 实现标准图卷积网络
- 包含特征变换和非线性激活
- 实现推荐功能

#### 3.3 LightGCN模型 (`app/models/lightgcn.py`)
- 已实现，无需修改

#### 3.4 LightGCN+KG模型 (`app/models/lightgcn_kg.py`)
- 已实现，需适配本地数据

#### 3.5 LightGCN+KG+GAT模型 (`app/models/lightgcn_kg_gat.py`)
- 实现融合图注意力机制的增强模型

### 4. 模型训练流程

#### 4.1 数据预处理
- 加载本地数据
- 构建用户-物品交互矩阵
- 构建知识图谱特征
- 数据分割（训练集/测试集）

#### 4.2 模型训练
- 初始化模型
- 设置训练参数
- 执行训练过程
- 保存模型权重

#### 4.3 模型评估
- 在测试集上评估模型
- 计算Precision、Recall、NDCG等指标
- 生成评估报告

### 5. 训练脚本实现

#### 5.1 训练脚本 (`train.py`)
- 支持命令行参数
- 支持选择不同模型
- 支持设置训练参数
- 支持评估和结果输出

#### 5.2 评估脚本 (`evaluate.py`)
- 加载预训练模型
- 在测试集上评估
- 生成详细的评估报告

### 6. 依赖管理

#### 6.1 依赖更新 (`requirements.txt`)
- 确保所有必要的依赖已安装
- 支持PyTorch和PyTorch Geometric

## 六、风险与应对

### 1. 数据质量问题
- **风险**：本地数据质量可能不如数据库数据
- **应对**：提供数据验证和清洗工具

### 2. 模型复杂度问题
- **风险**：复杂模型可能训练时间长
- **应对**：提供模型选择和参数调整选项

### 3. 内存限制问题
- **风险**：大规模数据可能导致内存不足
- **应对**：实现数据分批处理和内存优化

### 4. 依赖兼容性问题
- **风险**：不同版本的依赖可能导致冲突
- **应对**：提供详细的依赖版本要求
